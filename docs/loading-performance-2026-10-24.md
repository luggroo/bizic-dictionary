# 首页加载优化与验证

首页现在直接使用 HTML 中的小份目录资料，导航、搜索入口、语言和拼音偏好可先操作。词典索引、词条出处、语法、语料和比较材料在进入对应功能时加载。

## 冷缓存限速测量

本地 Chromium，手机视口 390 × 844，下载 1.6 Mbps、延迟 150 ms、CPU 降速 4 倍、禁用缓存。下表为一次前后对照；基线为 `9d640d9`。

| 指标 | 优化前 | 优化后 |
|---|---:|---:|
| 首页可操作时间 | 15.98 秒 | 1.12 秒 |
| 首次内容绘制 | 0.78 秒 | 0.77 秒 |
| 首次加载传输量 | 2.84 MB | 83.3 KB |
| 初始 JavaScript 请求 | 40 | 10 |
| 初始 JavaScript 压缩体积 | 679.7 KB | 40.0 KB |
| 首页独立数据包请求 | 1 | 0 |

主要收益是减少首页可操作前的等待。首次内容绘制时间接近。测量不包含真实内地网络的 DNS、跨境线路和托管节点延迟。

## 加载与恢复

- 首页的小译表在构建时从主译表提取，完整译表随功能合并到同一对象。首页也能保存南北拼音偏好。
- 页面按功能载入脚本和样式。词典索引、目录、语料与比较数据分别发布；首次进入语法不请求词典索引。
- 数据、脚本和样式读取包含响应正文的超时。通常为 20 秒，词典索引为 45 秒；可恢复错误最多自动重试两次，404 等错误直接显示恢复入口。失败的请求缓存会清除，手动重试能够重新请求。
- 页面切换以最后一次导航为准；等待中的页面不会覆盖新页面。加载占位内容也不会覆盖返回时应恢复的滚动位置。
- 文献全文读取最多同时启动六个工作任务。不支持流式解压的浏览器在需要时载入 gzip 解压工具。
- 脚本采用内容指纹；词典内容未变化时继续复用已缓存数据。旧版完整数据包仍保留，已有链接和缓存页面可以继续使用。

## 验证

通过请求超时、响应正文停滞、503 重试、404、取消、损坏响应恢复测试；通过页面手动重试、快速切页、词条分享链接、旧式解压、首页拼音偏好测试。

通过原有导航的 14 组浏览器检查，覆盖七个入口、词条与语料详情、筛选、分页、返回/前进、语法引用、记音证据和 84 组语言／窗口组合（320–1280 px）；浏览器异常与失败的脚本、样式、字体和数据资源均为零。手机语法章节跳转与借词拼音显示另行检查通过。

完整检索数据压缩文件的 SHA-256 在优化前后相同：

`e18b7009927ede28ce6c3f2c2a9c751fdd529ecca69ad3b5339b18e40bc2432e`

16,577 条词条、原始出处、IPA、声调、分词和借词范围保持一致；198,974 项预处理检索检查通过。

## 静态托管与 CDN

后续以内地实际访问中的首页可操作、首次查词和语法打开时间决定是否调整静态托管或 CDN。构建产物仍是标准静态目录，迁移时可保留现有域名路径和词条链接。

HTML 应及时重新验证；内容指纹脚本和版本化数据可以使用长缓存。CDN 需把 `v` 参数计入缓存键，并将同一版本的 HTML、功能脚本和数据一起发布。
